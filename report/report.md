## 1. Введение и постановка задачи

- **Цель проекта:** создаю ML модель детекции фрода в блокчейне Ethereum по датасету транзакционной активности
- **Формулировка задачи:** классификация
- **Обоснование метрики качества:** Основная - F1-score, поскольку нужно оценить бинарную классификацию с дисбалансом классов. Также ROC-AUC - дополнительная и точность как вспомогательная. Обоснование - Accuracy неустойчив при дисбалансе, F1 учитывает precision и recall → оптимален, ROC-AUC показывает качество ранжирования

## 2. Поиск и описание данных

- **Источник данных:** [датасет](https://www.kaggle.com/datasets/vagifa/ethereum-frauddetection-dataset) нашла по запросу "fraud ethereum" kaggle, выбрала, потому что работаю над похожими проектами
- **Описание датасета:**
  - 9841 строка
  - 51 столбец
  Целевая переменная: FLAG (бинарная классификация).
  - класс 0: ~77.9%
  - класс 1: ~22.1%
  Таким образом, датасет умеренно несбалансирован, что важно учитывать при выборе метрик и обучении модели.
- **Признаки включают**:

  - агрегаты транзакций (количество, интервалы)
  - статистики по ERC20 токенам
  - временные характеристики
  - категориальные признаки (тип токена и т.д.)

## 3. Обработка и подготовка данных

- **Полная очистка:**
  - Удаление нерелевантных признаков:
Unnamed: 0, Index — технические индексы
Address — уникальный идентификатор (неинформативен для модели)
  - Обработка пропусков: в некоторых ERC20-признаках присутствуют NaN
- **Пропуски** заменялись:
  - либо на 0 (если логично: отсутствие транзакций)
  - либо на категорию "unknown" (для категориальных)
- **Дубликаты**:
  - Проверка на дубликаты строк
  - Удаление при наличии
- **Выбросы:**
  - признаки типа max val sent имеют heavy-tail распределение, см. ниже
  - применялись:
    - логарифмирование (log-transform)
    - clipping (ограничение экстремальных значений)
- **Типы данных**:
  - числовые признаки приведены к float/int
  - категориальные - к category или закодированы

- **Работа с фичами** (feature engineering)

  Исходное количество признаков: ~51

  Выполненные преобразования:

  - Удаление лишних признаков (см. выше)
  - Создание новых признаков:
    - соотношения:
    sent / received transactions
    - плотность активности:
    transactions / time
    - агрегаты:
    средние значения по токенам
  - Кодирование категориальных признаков:
    One-Hot Encoding для токенов
  - Масштабирование:
    StandardScaler / MinMaxScaler для числовых признаков

Итог: пространство признаков стало более информативным и пригодным для моделей.


- **Визуализации:** 

В EDA использовались:

  - распределения признаков (гистограммы)
  - корреляционная матрица
  - boxplot для выявления выбросов
  - анализ зависимости признаков от FLAG

Ключевые наблюдения:

  - некоторые транзакционные признаки сильно коррелируют с целевой переменной
  - распределения многих признаков асимметричны (long-tail)
  - есть информативные группы признаков (ERC20-активность, например)

- **Сплит данных:**
  - Использовался стандартный pipeline:

    - train: 70%
    - validation: 15%
    - test: 15%


Избежание утечки данных:

  - масштабирование обучалось только на train
  - encoding - только по train
  - test не использовался при подборе гиперпараметров

Поскольку данные не временные (нет явной временной зависимости), random split допустим.
